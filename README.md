# SponsorBar Terminal

A native macOS proof-of-concept client that renders SponsorBar creatives in an interactive terminal and uses SponsorBar's production lease and completion protocol.

> [!IMPORTANT]
> This repository implements a specifically approved SponsorBar terminal-placement proof of concept. It does not grant third parties permission to submit terminal impressions. Confirm authorization with SponsorBar before using it with an earning account.

This is an independent integration, not an official SponsorBar release.

## Requirements

- macOS 14 or newer
- A Mac with Secure Enclave support
- Swift 6.3 or a compatible Xcode toolchain
- A SponsorBar account authorized for terminal-rendered impressions

## How it works

1. The client reads the existing SponsorBar device ID, bearer token, and Secure Enclave signing key from macOS Keychain, or creates them through `--pair`.
2. It requests a creative from SponsorBar's production delivery endpoint using the SponsorBar 1.0.11 request schema.
3. It prints the sponsor name, slogan, destination, logo URL, and campaign ID to an interactive terminal.
4. It submits completion only after 60 displayed seconds and before the lease expires.

No completion is submitted when the process exits, receives `SIGINT`, `SIGTERM`, or `SIGHUP`, sleeps through the interval, loses account eligibility, or reaches lease expiry first. The regular SponsorBar app must not be running because both clients would contend for the same device lease.

Terminal process lifetime and rendering are the approved visibility condition for this integration. The client does not use terminal focus, window occlusion, display lock state, menu-bar state, or status-item geometry to decide whether the creative is visible. It still samples awake, unlocked, and recent-activity values for protocol telemetry.

## Build and test

```sh
git clone https://github.com/rohan-patra/sponsorbar-terminal.git
cd sponsorbar-terminal
swift test
swift build -c release
```

The executable is written to `.build/release/sponsorbar-terminal`.

## Usage

Quit the regular SponsorBar app first.

Run one delivery result or paid minute:

```sh
.build/release/sponsorbar-terminal --once
```

Run continuously:

```sh
.build/release/sponsorbar-terminal
```

Pair a Mac that does not already have SponsorBar credentials:

```sh
.build/release/sponsorbar-terminal --pair
```

Pairing creates a Secure Enclave P-256 key, starts the SponsorBar browser verification flow, obtains an Apple DeviceCheck token, and stores the resulting device credentials in macOS Keychain. A plain SwiftPM executable may not receive a DeviceCheck token under every signing configuration. In that case, package it as a signed macOS command-line app using a SponsorBar-approved bundle identifier.

Available flags:

```text
--pair   Pair this Mac instead of requesting creatives
--once   Exit after one delivery result or paid minute
--help   Show help
```

## Production behavior

There is one operating mode. The client always uses:

- API origin: `https://sponsorbar.io`
- Keychain service: `com.kickbot.sponsorbar`
- Request compatibility version: `1.0.11`

There is no alternate backend or local-server mode. Authenticated requests use a timestamped nonce, SHA-256 body digest, and an ECDSA P-256 signature generated by the paired Secure Enclave key. Secrets are loaded at runtime from Keychain and are never stored in this repository.

## Troubleshooting

- **SponsorBar is running:** Quit the menu-bar app before starting this client.
- **Standard output is not interactive:** Run the executable directly in a terminal instead of piping or redirecting it.
- **Credentials are missing:** Run with `--pair`, or pair through the regular SponsorBar app first.
- **Keychain denies access:** Approve the macOS Keychain prompt for the built executable.
- **Lease has less than 60 seconds remaining:** The client refuses the lease and stops after three consecutive short leases rather than repeatedly contacting production.

## Development

Run the full local verification before submitting changes:

```sh
swift format lint --recursive Sources Tests Package.swift
swift test
swift build -c release
```

Tests use synthetic model data and do not contact SponsorBar. Do not add credentials, exported Keychain data, production response captures, or real device identifiers to fixtures. See [CONTRIBUTING.md](CONTRIBUTING.md) and [SECURITY.md](SECURITY.md).
